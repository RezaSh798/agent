# Agent Repository (Commands, Skills & Agents)

مجموعه دستورات صریح (Slash Commands)، مهارت‌های پس‌زمینه خودکار (Background Skills) و ایجنت‌های سفارشی (Custom Agents) برای هوش مصنوعی کدنویسی و ابزارهای Agentic (به‌ویژه Kilo).

---

## 🏛️ ساختار معماری (Architectural Structure)

این مخزن قابلیت‌های دستیار را به سه بخش مجزا و شفاف تفکیک کرده است:
1. **دستورات صریح کاربر (`commands/`):** ماکروها و گردش‌کارهای مشخصی که مستقیماً توسط کاربر از طریق اسلش‌کامند (مانند `/code-review` یا `/spec-runner`) فراخوانی می‌شوند.
2. **مهارت‌های پس‌زمینه (`skills/`):** دانش رویه‌ای و متدولوژی‌های زمینه‌ای که به صورت خودکار رفتار ایجنت را در مواجهه با تسک‌های مرتبط (مانند ریفکتور ماژول‌ها) هدایت می‌کنند.
3. **ایجنت‌های سفارشی (`agents/`):** تعاریف ایجنت‌ها و ساب‌ایجنت‌های تخصصی با نقش‌ها و دسترسی‌های اختصاصی (مانند `task-runner`).

```text
.
├── agents/
│   └── task-runner.md
├── commands/
│   ├── code-review.md
│   ├── gitlab-issue.md
│   ├── prompt-architect.md
│   ├── spec-kit.md
│   └── spec-runner.md
├── skills/
│   └── refactor-module/
│       └── SKILL.md
└── README.md
```

## ⚡ دستورات صریح (Commands)

دستورات صریح ماکروها و گردش‌کارهای مشخصی هستند که با تایپ اسلش‌کامند در محیط CLI / چت ایجنت اجرا می‌شوند.

### 🔍 [`/code-review`](./commands/code-review.md)
بررسی خودکار، دقیق و عمیق کدهای شاخه جاری در مقایسه با شاخه مرجع (`develop` یا `master`) بر اساس سه اصل:
1. **صحت عملکردی و باگ‌ها (Functionality & Correctness)**
2. **معماری تمیز و حفظ مرزبندی لایه‌ها (Clean Architecture)**
3. **کد تمیز و نگه‌داری‌پذیری (Clean Code & Readability)**

- **آرگومان ورودی:** `$ARGUMENTS` (اختیاری): نام شاخه مبنا (پیش‌فرض: `origin/develop` یا `origin/master`).
- **ویژگی‌ها:** تولید گزارش ساختاریافته به زبان فارسی جهت درج در کامنت Merge Request گیت‌لب با تمرکز انحصاری بر تغییرات MR (`git diff`).

---

### 🦊 [`/gitlab-issue`](./commands/gitlab-issue.md)
تبدیل یادداشت‌های خام، گزارش‌های باگ یا درخواست‌های فیچر به ایشوهای استاندارد و ساختاریافته گیت‌لب بدون حل مستقیم کد (در نقش Issue Writer / Technical PM).

- **آرگومان ورودی:** `$ARGUMENTS`: متن یادداشت یا توضیحات خام باگ/فیچر.
- **ویژگی‌ها:** عنوان انگلیسی قراردادی، بدنه فارسی ساختاریافته، Quick Actions گیت‌لب (مایلسون، اساین و لیبل‌ها) در یک کدبلاک آماده کپی.

---

### 🎯 [`/prompt-architect`](./commands/prompt-architect.md)
تبدیل توضیحات خام تسک به پرامپت‌های مهندسی‌شده، ساختاریافته و استاندارد برای ایجنت‌های هوش مصنوعی.

- **آرگومان ورودی:** `$ARGUMENTS`: ایده یا شرح اولیه تسک.
- **ویژگی‌ها:** تحلیل نیازمندی‌ها و ارائه پیشنهادات بهبود، تولید پرامپت نهایی انگلیسی در یک کدبلاک منسجم با اصول ضدتوهم (Anti-hallucination) و ساختار استاندارد.

---

### 📋 [`/spec-kit`](./commands/spec-kit.md)
توسعه مبتنی بر مشخصات (Spec-Driven Development) با استفاده مستقیم از ابزار رسمی **GitHub Spec Kit (`specify` CLI)** جهت تبدیل ایده‌ها به اسناد مشخصات، پلن معماری و تسک‌های اجرایی اتمیک.

- **آرگومان ورودی:** `$ARGUMENTS`: عنوان یا خلاصه ایده فیچر جدید.
- **ویژگی‌ها:** شفاف‌سازی تعاملی پیش از اجرا، اجرای الزامی اسکریپت‌های رسمی Spec Kit (`create-new-feature.sh`، `setup-plan.sh`، `setup-tasks.sh`) و ایجاد برنچ و فایل‌های استاندارد.

---

### ⚙️ [`/spec-runner`](./commands/spec-runner.md)
اجرای ترتیبی و گام‌به‌گام تسک‌های مشخص‌شده در اسناد Spec یا آرگومان‌های ورودی با استفاده از ساب‌ایجنت‌های ایزوله (`task-runner`).

- **آرگومان ورودی:** `$ARGUMENTS`: مسیر فایل تسک‌های مشخصات یا لیست تسک‌ها.
- **ویژگی‌ها:** توالی‌بندی تسک‌ها، اجرای مستقل هر تسک با کانتکست تازه از طریق ساب‌ایجنت ایزوله، اعتبارسنجی مرحله‌ای و ارائه خلاصه وضعیت نهایی.

### 📥 نحوه نصب و راه‌اندازی دستورات (Commands Setup)

دستورات به صورت فایل‌های مارک‌داون مستقل در مسیر پوشه `command/` قرار می‌گیرند:

#### ۱. نصب سراسری (Global):
برای در دسترس بودن دستورات در تمامی پروژه‌ها، فایل‌های `commands/` را در پوشه کانفیگ گلوبال Kilo کپی یا سیم‌لینک کنید:

```bash
# ایجاد دایرکتوری دستورات گلوبال Kilo
mkdir -p ~/.config/kilo/command

# کپی کردن تمام دستورات
cp commands/*.md ~/.config/kilo/command/

# یا ایجاد سیم‌لینک (Symlink) جهت به‌روزرسانی خودکار با پول کردن ریپو
ln -sf $(pwd)/commands/*.md ~/.config/kilo/command/
```

#### ۲. نصب محلی در پروژه (Project-Level):
برای فعال‌سازی دستورات فقط در یک پروژه مشخص:

```bash
# در ریشه پروژه مقصد
mkdir -p .kilo/command
cp /path/to/agent/commands/*.md .kilo/command/
```

## 🧠 مهارت‌های پس‌زمینه (Skills)

مهارت‌ها دانش رویه‌ای و استانداردهایی هستند که به صورت خودکار توسط ایجنت در زمان انجام تسک‌های مرتبط بارگذاری و استفاده می‌شوند.

### 🛠️ [`refactor-module`](./skills/refactor-module/SKILL.md)
مهارت ریفکتورینگ عمل‌گرایانه، امن و نگه‌داری‌پذیر ماژول‌های Node.js (جاوااسکریپت و تایپ‌اسکریپت) بدون ایجاد تغییرات مخرب (Breaking Changes) یا پیچیدگی بیش از حد (Over-Engineering).

- **ویژگی‌ها:**
  - مستندسازی استاندارد با JSDoc برای متدها، کلاس‌ها، پارامترها و مقادیر بازگشتی.
  - انطباق با اصول پنج‌گانه SOLID (شکستن توابع بر اساس SRP، استفاده از جدول/نگاشت استراتژی برای OCP، رعایت LSP، اینترفیس‌های کوچک با ISP، و وارونگی وابستگی با DIP).
  - استفاده از Guard Clauses و Early Returns جهت کاهش پیچیدگی و تورفتگی کدهای شرطی.
  - استخراج Magic Values به ثابت‌های فریز شده ماژول.
  - ارتقای کدهای ناهمگام به `async/await` و بهینه‌سازی تمیز پرتاب خطاها.
  - حفظ کامل سازگاری کدهای موجود (Zero Breaking Changes).

---

### 📥 نحوه نصب و راه‌اندازی مهارت‌ها (Skills Setup)

مهارت‌ها به فرمت استاندارد `SKILL.md` داخل دایرکتوری با نام همان مهارت ذخیره می‌شوند:

#### ۱. نصب سراسری (Global):
کپی یا لینک کردن پوشه مهارت به مسیر سراسری مهارت‌ها:

```bash
# مسیر سراسری استاندارد Agent Skills
mkdir -p ~/.agents/skills
cp -r skills/refactor-module ~/.agents/skills/

# یا ایجاد سیم‌لینک (Symlink)
ln -sfn $(pwd)/skills/refactor-module ~/.agents/skills/refactor-module
```

#### ۲. نصب محلی در پروژه (Project-Level):
```bash
# در ریشه پروژه مقصد
mkdir -p .kilo/skills
cp -r /path/to/agent/skills/refactor-module .kilo/skills/
```

#### ۳. نصب از طریق Skills CLI:
```bash
npx skills add RezaSh798/agent@refactor-module -g
```

## 🤖 ایجنت‌های سفارشی (Agents)

ایجنت‌های سفارشی نقش‌ها و ساب‌ایجنت‌های تخصصی تعریف‌شده در Kilo هستند که محدوده دسترسی (Permissions)، حالت عملکرد (Mode) و دستورالعمل‌های اختصاصی را تعیین می‌کنند.

### 🏃 [`task-runner`](./agents/task-runner.md)
ساب‌ایجنت متمرکز بر اجرای اتمیک، تمیز و ایزوله تسک‌های کدنویسی و پیاده‌سازی بدون شلوغ کردن کانتکست سشن اصلی.

- **نوع ایجنت (Mode):** `subagent`
- **مجوزها:** دسترسی به ابزارهای `read`، `edit` و `bash` جهت بازرسی کد، اعمال تغییرات و اعتبارسنجی با تست/لینت.
- **ویژگی‌ها:** اجرای ایزوله یک تسک منفرد، پایبندی دقیق به الگوهای DDD و Clean Architecture، و ارائه خروجی ساختاریافته از فایل‌های تغییریافته و نتیجه اعتبارسنجی.

---

### 📥 نحوه نصب و راه‌اندازی ایجنت‌ها (Agents Setup)

فایل‌های ایجنت در مسیر `agent/` قرار می‌گیرند:

#### ۱. نصب سراسری (Global):
```bash
# ایجاد دایرکتوری ایجنت‌های گلوبال Kilo
mkdir -p ~/.config/kilo/agent

# کپی کردن تمام ایجنت‌ها
cp agents/*.md ~/.config/kilo/agent/

# یا ایجاد سیم‌لینک جهت همگام‌سازی خودکار
ln -sf $(pwd)/agents/*.md ~/.config/kilo/agent/
```

#### ۲. نصب محلی در پروژه (Project-Level):
```bash
# در ریشه پروژه مقصد
mkdir -p .kilo/agent
cp /path/to/agent/agents/*.md .kilo/agent/
```
